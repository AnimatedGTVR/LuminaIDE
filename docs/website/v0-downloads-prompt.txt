UPDATE THE EXISTING LUMINAIDE WEBSITE: DOWNLOADS, BUILD STUDIO AND A CLEANER LOOK

Apply this after the earlier website/changelog prompts. These instructions supersede their Liquid Glass, nine-theme and drifting-orb requirements. Preserve historical changelog entries as history.

1. Remove Liquid Glass from current feature copy, theme demos and FAQs. There are now seven bundled themes: Vanta Night, Graphite, Daylight, Ember, Nord, Dracula and Solarized Light. Remove glass badges, blur effects and animated background orbs. Use opaque surfaces, crisp borders, clear secondary text and restrained lavender accents. Vanta Night now uses background #151821, sidebar #10131B, border #2B3141, foreground #E8ECF4, muted #A0ABBE and accent #AC9BFF. Never advertise old glass themes as available.

2. Add a /download page, linked from the hero, navigation and footer. Show explicit choices for Windows x64, macOS Apple silicon, macOS Intel, Linux x64 and Linux ARM64. OS detection may highlight a suggestion but must never hide other downloads. On phones show all choices and explain that the editor runs on desktop computers. Windows ARM can try the x64 build through emulation; do not claim a native ARM Windows build.

3. Set REPO_URL to https://github.com/AnimatedGTVR/LuminaIDE in the site configuration and use it throughout. Fetch the latest published GitHub Release from that repository, server-side with caching. Resolve actual assets ending in -win-x64.zip, -osx-arm64.zip, -osx-x64.zip, -linux-x64.tar.gz and -linux-arm64.tar.gz. Match checksum sidecars by full archive name plus .sha256. Link only to assets actually returned. Display the release version from the API, never infer that an Unreleased feature has shipped. If no release exists, the network fails, the API is rate-limited, or an asset is missing, show "No published download available" for that choice with links to the Releases page and source build guide. Do not invent links or show fake successful downloads. Do not expose GitHub tokens to the browser.

4. Each card explains extraction and launch: Windows extracts the whole ZIP and runs LuminaIDE.exe, macOS moves LuminaIDE.app to Applications, Linux extracts and runs ./LuminaIDE. Archives bundle .NET; no SDK is needed to run them. Linux/Windows include optional binary installers for menu shortcuts. Note that Windows downloads are unsigned and Mac downloads are not Developer ID signed/notarized. Use normal OS approval flows; do not tell people to disable security globally. Linux requires glibc, X11/fontconfig and a desktop graphics stack; Android and Alpine/musl are not supported.

5. Add a "Build it yourself" section with tabs for Windows, macOS and Linux. Prerequisites: .NET 8 SDK, Rust stable, CMake 3.20+ and a C++17 compiler. Windows needs Visual Studio Build Tools (Desktop development with C++); macOS needs Xcode command-line tools; Linux needs its distribution's development tools. Link to docs/BUILDING.md on REPO_URL. Download source from GitHub's Code menu / source archive; never pipe a remote script directly into a shell.

6. Show Build Studio with the real docs/img/builder.png screenshot. Launch commands: double-click Build.cmd on Windows, open Build.command on macOS, ./build.sh --gui on Linux. The GUI requires the .NET 8 SDK and builds on first launch. It has Check tools, Build editor, Build + test, Create download, live logs, Stop and Save log. Terminal equivalents: ./build.sh --check, ./build.sh test, ./build.sh package; Windows uses .\build.ps1 instead. Packages and SHA-256 files appear in dist/ and target the host computer.

7. Add "Build from any device" with a clear explanation: fork the repo, enable Actions, choose Actions → Downloads → Run workflow, then download the completed platform artifact. Link to REPO_URL/actions/workflows/release.yml. This can be triggered from phone/tablet browsers; compilation happens on GitHub, not on the phone. Manual artifacts expire after 14 days and require GitHub access. This does not imply LuminaIDE runs on iOS/Android. Usage quotas and runner availability depend on the GitHub account.

8. Use normal accessible links, labelled tabs, visible keyboard focus and a readable mobile layout. Honour reduced motion. Test success, missing release, missing asset and API error states. Preserve all earlier historical release entries, and clearly label new build/appearance work as Unreleased until it is included in a published release.
